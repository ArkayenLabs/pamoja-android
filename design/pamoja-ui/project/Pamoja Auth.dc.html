Authentication

Continuation, section 2C

Real accounts, three methods, Google first. The governing constraint is the one in the brief: signing in must feel like keeping what you already have. So every screen that a returning anonymous user can reach names their actual groups by name and count, and the word "create" never appears near their existing data.

Global by default. The country picker is searchable and defaults to the device locale rather than a hardcoded market, and because emoji are banned everywhere in this product the list uses ISO codes and dial codes instead of flags, which is also better for screen readers. The OTP field is drawn from the length the server declares, so the six box layout below is one instance and not a hardcoded assumption. A four box variant is shown alongside it.

Landing and phone

The landing screen answers "why do I need an account" before it asks for anything, in one sentence tied to a real consequence: a new phone. Google is the filled ember button because it is the one tap path, phone and email are outline rows below it, and the three sit in a single visual family so the choice reads as three doors rather than one recommendation and two afterthoughts.

2C Auth landing — the Google mark is a placeholder here; the real asset ships from Google's brand kit and must not be redrawn. Note the reassurance card sits above the buttons, not buried in a footnote, and the legal line stays at 12px rather than being shrunk to hide it.

One time code

Boxes are generated from the length the server declares, so a four digit market and a six digit market both work without a redesign. Both are shown here. The resend timer counts down inside the row rather than swapping the control out, autofill from the SMS fills all boxes at once, and the "wrong number" escape sits directly under the boxes where a mistyped digit is discovered, not buried at the bottom.

2C OTP, sent and verifying — the number is restated in full so a wrong digit is caught here rather than after a failed code. The resend row is disabled with a live countdown, which is the honest version of an inactive control: it says exactly when it will work.

§2C

Linking and Settings

This is where the "keeps what you have" rule is load bearing. The prompt shown to an existing anonymous user never says create, sign up or start. It names their groups, states the risk in one concrete sentence about changing phones, and offers a Not now that actually works. The banner is dismissible per session but returns, because the risk is real and silent data loss is the worst outcome this product can produce.

2C Account linking prompt — the groups at risk are listed by name and colour, which is the difference between an abstract warning and a personal one. Nothing is blocked behind this: Not now is a full width, fully legible control, not a grey whisper.
